# Task 6 recovery — bounded student rollout retries and durable capture audit

Changed only `src/bufogen/train_rl.py` and new `tests/test_rl_recovery.py`. Original source snapshot is under `task6-before/src/bufogen/train_rl.py`. No paid calls, optimizer calls, deployments or runtime agent/model/scorer changes were made by this worker.

A single missing rollout now has at most three generation attempts. Only OpenAI connection/timeout errors or HTTP 429/5xx during student `agent.generate` qualify. Backoffs are 2 and 4 seconds. A new agent/capture and distinct `:attemptN` conversation ID are used for each retry at the same step/rollout index. The existing OpenAI client may internally retry requests as before; the new bound is on complete rollout attempts. Judge/capture validation/model logging/optimizer/registry errors are outside this retry scope. `backend.train` is still called once, never automatically retried.

Before a rollout, `captures/step-N-rollout-I-attempt-J.json` is durably written as started. On failure it retains the actual ART exchanges captured before interruption (which may be empty), exception type/status, retry decision and actual partial-generation record when available. No synthetic successful choices or trajectories are constructed. Failed partial captures never enter the training group. On success, actual capture bytes and generation ID are saved before validation/scoring. After scoring, the same record gains reward and metrics. All record writes are atomic, fsync the file and directory, and reject unsupported serialization instead of dropping fields. Real Pydantic ART exchanges are serialized via their JSON model dump; SimpleNamespace support only accommodates existing boundary-test fixtures.

Local attempt directories are exclusively created before W&B API construction/model registration. Any existing directory is refused, including failed/interrupted attempts; its state/evidence cannot be overwritten. Input dataset/calibration validation still happens first. This is deliberately not checkpoint-resume machinery. Root can use a fresh attempt name only after checking the remote checkpoint; the existing SFT-identity verification will again ensure the service checkpoint matches immutable SFT bytes. Names must be one directory component.

Training state records the rollout attempt budget. Existing state transitions and positive-checkpoint SFT verification remain. A training-side timeout leaves `status=failed` and `training_from_step`; replay of the local attempt is refused.
